## OOP

OOP funguje na principu tvorby rodičů a jejich dětí (v programování ano zní to divně). Toho dosáhneme tvorbou jednotlivých objektů
ty které nejsou ničím rozšířeny (=není element ze kterého pocházejí) jsou naši rodiče, objekty které vycházejí z těchno class (nebo jiných dětí) 
jsou dětmi. Dítě zdění metody a proměnné svého rodiče.
> **Metoda** - funkce která patří objektu, skoro vždy bude pracovat se svými proměnnými

Důvod proč vytváříme děti je rozšíření jejich rodiče, děti mohou přepisovat metody, mít více proměnných, nebo specifické metody

*Proč vlastně používáme OOP?* ...důvodů může být více, např jazyk jako Java je na nich velice založená a budeme je muset 
použít pokud chceme něco vytvořit, ale hlavním důvodem je přehlednost a lehčí práce kdy potřebujeme kontrolovat hodně proměnných 
které budeme zpracovávat stejným způsobem. Př:
```text
Máme videohru a protřebujeme vytvořit velké množství NPC,
 ty mají základní vlastnosti jako X Y souřadnice, HP, atd...
 
 Pokdud by jsme nepoužily OOP z kódu by se stalo cca toto:
 X_npc_1 = 133
 X_npc_1 = 84
 X_npc_1 = 1389523
 X_npc_1 = 4984
 X_npc_1 = 96
 X_npc_1 = 85
 ...
 
 a to nebereme v potaz jejich vlastnosti, s OOP lze vytvořit:
 
 // Základní rodič 
 class NPC (promenné)
 | > .move()
 | > .die()
 | > .speak()
 
 // Obchodník je dítě NPC a umí obchodovat
 class NPC_trader Extends NPC (...)
 | > .trade()
 | > .sell()
 
 // Podobný jako Obchosdník ale místo obchodování umí bojovat
 class NPC_guard Extends NPC (...)
 | > .fight()
 | > .defend()

 // Pes není schopen mluvit proto upravíme metodu od jeho rodiče NPC aby nemohl mluvit  
 class NPC_dog Extends NPC (...)
 | > .speak() { thow Error("Dogs dont speak!") }
 
 // Tento Pes stále nebude mluvit ale může bojovat jeho rodičem tedy není NPC ale NPC_dog
 class NPC_guard_dog Extends NPC_dog (...)
 | > .fight()
 
```
